Code Development Lifecycle: Planner, Reviewer, Builder Interaction

A star-topology orchestration lifecycle governed by dual formal verification gates (PLAN_PASS & REVIEW_PASS) and an airlocked blind barrier isolating test execution from private review criteria.

ISOLATION INVARIANT

The Blind Barrier

Builder operates strictly inside an airlocked execution chamber, receiving only Planner-sanitized Build Plans and concrete remediation instructions. Builder never sees Review Plans, private review criteria, or raw Review Findings, guaranteeing uncompromised test independence and preventing benchmark gaming.

VERIFICATION GATES

Dual Formal Gates

The lifecycle enforces two mandatory sequential checkpoints: GATE 1 (PLAN_PASS) ensures architectural consensus and review criteria coverage before any code is generated; GATE 2 (REVIEW_PASS) confirms objective test verification and zero unresolved Blocker/Major findings before human commit authorization.

COORDINATION TOPOLOGY

Star Topology

Builder and Reviewer maintain zero direct communication channels. Planner stands at the physical and logical hub as the sole coordinator, airlock filter, and living memory curator (AGENTS.md), eliminating peer interference, circular debates, and state synchronization leaks.
